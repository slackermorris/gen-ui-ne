Problem

Nine component classes each carried a byte-for-byte copy of the catalogue-projection body — the brittle ast.annotations["description"] as string read and the Schema.Struct shape — differing only in the class name.

Solution

Extract a single generic catalogueElementOf(type, propsFields, ast) helper that owns the projection; each toCatalogueElement() becomes a two-line delegation that preserves its precise return type.

Wins

  • Locality: projection bug fixed once
  • Leverage: one helper, nine call sites
  • Deep module: small interface, lifted logic
  • Deletion test: complexity vanished, not moved
  • One cast, not nine
  • Interface unchanged: Catalogue untouched

Validation

Tests green: vp test run — 7/7 across 2 files. Type-clean: vp check --no-fmt introduces zero new errors or warnings (3 pre-existing errors in catalogue.ts are unchanged, out of scope). Diff is net −35 lines, isolated to one file.

Redundant per-class JSDoc mirroring the annotation

Fully free-function projection (drop the statics)

A single free function over the class would delete the statics entirely, but the generic Omit<C["fields"], "type"> projection fights Effect's Fields constraint, forcing casts. The delegating form keeps types precise with no casts — the boring, inevitable shape.
